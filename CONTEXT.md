# Clutch — контекст для следующей сессии

Обновлено: **2026-10-12**. Описание R1–R9e ниже собрано на checkpoint `290b696`
(2026-10-02); с тех пор продукт сильно изменился, актуальная картина — в разделе
«Что изменилось после R9e». Это снимок состояния, а не обещание готовности к релизу.
Строки R1–R9e сохранены как история: где они говорят о гонке до 100%, это
`race-to-100-*`, больше не основной режим.

## Что строим

Русскоязычную mobile-first Telegram Mini App: ответь на вопрос, получи попытку
в skill-мини-игре, преврати качество попытки в прогресс до 100% в своём темпе.
Прежний слоган «Knowledge earns the attempt. Skill wins the game.» больше не
описывает продукт: тезис «точность решает» замером не подтвердился и снят (DEC-01).

Основной режим — **соло-забег до 100%**, а не гонка. Запись предыдущего
прохождения (или бот) показывается на полосе, но завершить забег не может;
сравнение идёт по `solo_score = круги / пар набора`. Соперник **не играет
одновременно**. Общий интерфейс показывает проценты/полосы, а гвоздь виден только
в мини-игре. Дартс — возможное развитие, не текущая задача.

## Что уже есть

- npm-monorepo: React/Vite в `apps/web`, Hono/Cloudflare Workers в `apps/api`,
  типы, контент и scoring в `packages/shared`; хранилище матчей — D1.
- Полный прототип цикла: главная → категория → соперник → вопрос → разбор →
  молоток при верном ответе → результат; профиль и локальная статистика.
- Игровые категории: «Общие знания» (`general`, по умолчанию с 2026-10-12),
  география, «Другие флаги» (id `history`), языки. Размер
  набора покатегорийный (см. ниже), таймер 15 секунд, выбор ответа и открытый ввод.
  Примерно 30% открытых вопросов относится к географии; две другие категории
  сейчас только с вариантами.
- Онлайн-матч получает вопросы от API: сохранённый набор соперника либо новый
  набор из общего генератора. Локальная генерация доступна только по явному
  выбору практики после ошибки старта.
- API создаёт прохождение, выбирает запись соперника, сохраняет результаты
  раундов и отдаёт leaderboard. Start/complete требуют проверяемую identity:
  Telegram initData либо подписанную браузерную guest-сессию; завершение сверяет
  владельца до возврата или записи результата.
- Есть звуки, SDK Telegram и обработка viewport/safe areas. Слово `challenge` в
  коде означает «бросившего вызов» в реванше (`challenger_run_id`).
- Общий Match HUD уже отделён от сцены молотка. Убраны старые спрайты с главной,
  общих экранов и результата; внутри молотка они пока остались.
- Share отправляет текст **со ссылкой на игру**: `lib/share.ts` строит payload и
  выбирает стратегию Telegram `shareURL` → `navigator.share` → копирование,
  карточка результата видна всегда, локальная практика помечена как
  несохранённая. Ссылка ведёт на `/api/share` (OG-страница с картинкой и счётом, редирект на `TELEGRAM_MINI_APP_LINK`); имя соперника только для `matchSource === 'player'`.
  Экспортируемой картинки по-прежнему нет. По документации SDK `shareURL`
  закрывает мини-приложение; на телефоне это не проверено. Полноценная карточка
  с картинкой и кнопкой требует `shareMessage` и bot-side
  `savePreparedInlineMessage` — не реализовано.
- R1a: `packages/shared/src/matchRules.ts` — чистое применение раунда,
  проверка последовательности, исход и пригодность ghost, с отдельными тестами.
- R1b: API применяет эти правила, хранит версию/config и полную копию соперника,
  принимает только законный финиш и фильтрует пул по пригодности/совместимости.
  Раннее поражение сохраняется, но не становится ghost. В start добавлены
  `conditions`; старый формат completion сохранён.
- R1c: клиент проверяет серверные conditions и транскрипт соперника, ведёт
  прогресс и завершение через те же shared-правила. Локальный Alex
  нормализуется под реальные id вопросов и обрезаются на первом достижении 100%;
  результат показывает число фактически сыгранных вопросов.
- API после R1 разнесён по `auth`, `matches` и `routes`; `index.ts` остаётся
  компактной точкой сборки, системные endpoints находятся в `routes/system.ts`.
  Текущий Alex описан `BotProfile`, а фабрика позволяет добавлять
  будущие профили сложности без изменения HTTP-маршрутов или D1-кода.
- Чистое состояние клиентской сессии и переходы вынесены в `gameSession.ts`;
  `useGameState.ts` оставляет React, сеть, analytics и отправку результата.
  Online/local и точные completion-prefix покрыты unit-тестами.
- R2a: браузер лениво получает семидневный HMAC guest token и продлевает его
  с тем же subject; Telegram отправляет `Authorization: tma`. `playerId` больше
  не принимается из тела. Требуется отдельный `SESSION_SIGNING_SECRET`.
- R2b: start/complete читают JSON с байтовым пределом 1/16 KiB; раундов не
  больше 10, ограничены id, ответ и время. Guest, start, complete и leaderboard
  защищены нативным Cloudflare Rate Limiting binding: 30 запросов за 60 секунд
  в отдельных bucket по IP либо проверенному player id.
- R3b/R3c: completion сначала попадает в versioned localStorage-очередь без
  auth token. Она переживает reload, использует single-flight и до четырёх
  transient-попыток с backoff/`Retry-After`; terminal 4xx не повторяются.
  Экран показывает pending/saved/error или честный локальный режим. Валидный
  ACK того же matchId сверяет серверные progress/correct/rounds и только после
  этого записывает отдельную confirmed-online статистику с dedup по matchId.
- R4: matchmaking имеет явные loading/ready/error. Имя показывается только после
  валидного ответа; player/bot/local подписаны честно. Back отменяет
  запрос, late response игнорируется, start/replay защищены от двойного запуска.
  Online replay создаёт новый run; local остаётся своим режимом.
- R5a: молоток считает position по active elapsed time (triangle wave), ограничивает
  длинный кадр 50 мс и ставит попытку на паузу при hidden. Shared distance thresholds
  теперь одновременно определяют scoring и все вложенные зоны. Config 0.8/0.85/0.15
  делал старые runs несовместимыми ghost, без rulesVersion/D1 migration
  (значения устарели: зоны и скорость маркера позже изменены, см. ниже).
- R5b: 15-секундный вопрос считает остаток от абсолютного deadline. Время
  продолжает идти в фоне и синхронизируется при visibility resume. Единый gate
  разрешает только один answer/timeout; событие в точный deadline считается
  timeout, а отложенный feedback-callback очищается при размонтировании.
- R5c: pressure stage 0..3 считается по предыдущим non-miss skill results;
  target детерминирован question id, а зоны сужаются множителями 1/.9/.8/.7.
  Shared helpers едины для UI, gameSession и последовательной API-проверки.
  Версия условий гонки повышена (сейчас `race-to-100-v3`); v1/старый config
  исключены из ghost pool, незавершённые старые runs получают 409 без новой D1 migration.
- R7a: вопрос с обязательной картинкой создаёт 15-секундный deadline только
  после успешного `load`; до этого prompt и ответы скрыты. Ошибка показывает
  retry без timeout, повторный `load` не перезапускает timing. Текущая картинка
  грузится eagerly и целиком помещается через `object-fit: contain`.
- R7b: документ помечен как русский и разрешает pinch zoom. Resolution и Hammer
  имеют keyboard/focus/disabled semantics и one-shot guard; timer, HUD progress,
  timeout, результат удара и сохранение получили подходящие доступные роли без
  агрессивного live-countdown или двойного объявления результата.
- R7c: React root создаётся один раз и сразу показывает доступный loading shell;
  Telegram bootstrap ограничен 2,5 секундами и использует один cached Promise.
  Viewport монтируется в фоне и при позднем успехе подключает динамические CSS vars:
  App ждёт его не более 2,5 секунд, а BackButton от него не зависит. Системный Back виден только на безопасных
  экранах, а активный вопрос/разбор/молоток не сбрасывает. Layout использует
  динамическую высоту viewport; открытый ввод сохраняется в видимой области при
  появлении клавиатуры с lifecycle-safe cleanup.
- R8a: составлен [редакторский gate](docs/CONTENT_REVIEW.md) активного контента.
  В игре используются 197 стран, 44 флага («Другие флаги») и 37 языков, но генератор
  автоматически помечает их `approved` без построчных источников. Официальными
  источниками доказаны устаревшая столица Экваториальной Гвинеи (`gq`) и ошибка
  Боливии (`bo`); неоднозначные столицы, sensitive territories, history
  и languages поставлены в очередь проверки. Код в R8a не менялся; позже `bo`
  исправлен на Сукре и `gq` на Сьюдад-де-ла-Пас (по PLAYTEST_01). Остальные
  предложенные формулировки владельцем не утверждены.
- R8b(a): `generateMatch` сначала выбирает уникальные сущности без замещения,
  поэтому возвращает точное запрошенное число вопросов независимо от коллизий
  RNG. Для geography/history/languages пределы равны 197/44/37 (ёмкость генератора, не размер игрового набора); превышение и
  неверные `numQuestions`/`openRatio` дают `RangeError` до начала генерации.
  География сохраняет округлённую долю open-answer, остальные категории — MC-only.
- R8b(c): leaderboard выбирает одну фактическую лучшую completed-запись каждого
  `player_id`; имя и показатели больше не склеиваются из разных матчей, а смена
  имени не создаёт вторую entry. Top-50 использует progress, correct count,
  ранний `completed_at` и стабильный `id`. Сравнимость progress разных наборов
  и условий для публичного рейтинга по-прежнему не утверждена.
- R9a: tracked GitHub Actions CI проверяет push в `master` и pull request на
  Node 22.17.0 из `.nvmrc`: `npm ci`, unit/route tests, локальный Wrangler HTTP
  smoke и production preflight fixture с полным build. У workflow read-only
  permissions, timeout и cancel-in-progress; deploy и секретов нет. На GitHub
  этот workflow ещё не запускался, поэтому remote gate пока не подтверждён.
- R9: добавлены ручные runbooks [TESTING](docs/TESTING.md) и
  [RELEASE](docs/RELEASE.md). Они описывают локальный/Telegram walkthrough,
  production gates, D1/Worker/Pages порядок и rollback, но ни один remote шаг
  ими не считается выполненным.
- R9c: `GET /api/ready` проверяет D1 binding и текущую схему `match_runs`
  дешёвым read-only запросом без сканирования строк. При ошибке он возвращает
  обезличенный 503; `/api/health` остаётся liveness без обращения к D1.
  Route-сценарии с текущей/старой схемой и упавшим binding проверены локально;
  production endpoint не развёрнут и не проверен.
- R9d: `scripts/smoke-local.mjs` из одного npm command создаёт временные config
  и local D1, применяет текущие migrations, запускает настоящий Wrangler и по
  HTTP доказывает readiness, auth failure, bot → eligible A → точный ghost B и
  canonical повтор completion. Исправленный прогон завершился exit 0 и удалил
  temp; command включён в CI перед production preflight fixture/build. Он не
  проверяет browser offline/retry, legacy incompatibility, remote Cloudflare
  или deploy.
- R9e: production preflight валидирует шесть явных `CLUTCH_PRODUCTION_*`
  значений, запрещает reuse development Worker/D1/rate namespace и создаёт
  production Wrangler config только в temp. Fixture доказал Worker dry-run,
  production bindings, полный root build и exact API URL; temp удалён. Root
  deploy aliases удалены, а реальные deploy/remote/secrets остаются только
  ручными шагами release runbook. CI использует fixture вместо отдельного build.
  Default/fixture не оставляют config; только real-mode npm script
  `preflight:production:write-config` после успешных проверок создаёт ignored
  `apps/api/wrangler.production.generated.jsonc` без secrets и без overwrite
  для последующего review и ручных команд.
- Миграция `0002_match_conditions.sql` применена к локальной D1 2026-09-28.
  Старые строки сохранены, но имеют неизвестные условия и исключены из пула.
  Незавершённый legacy-матч получает 409: нужно начать новый.

## Что изменилось после R9e

Записано 2026-10-12 по фактам владельца и git log; подробности в PRODUCT/ARCHITECTURE.

- **Основной режим — соло-забег до 100% в своём темпе.** Запись соперника на
  полосе завершить забег не может. Результат — `solo_score = круги / пар набора`.
  Версии правил: `solo-to-100-v2` (соревновательный), `solo-practice-v1`
  (тренировка), `solo-friend-v1` (дружеская ссылка). Старая гонка
  `race-to-100-v3` удалена из кода 2026-10-13 (R12).
- **Основание — [PLAYTEST_01](docs/PLAYTEST_01.md).** Полный набор не доигран ни
  разу, пул из одних 100%-победителей, 93% ударов давали 18–25 очков из 25.
  Тезис «Знание даёт шанс, точность решает» не подтвердился и снят.
- **Молоток переделан:** зона идеального 0.15 → 0.06, полоса «хорошо» 0.35 → 0.28,
  скорость маркера вместо постоянной 0.8 меняется в 0.6–1.6 и выводится из хеша
  вопроса и стадии давления. Идеальных ударов около 21% вместо 60% — оценка, не
  замер на людях.
- **Новое:** реванш на новом наборе с одноразовым приглашением и сроком; плановый
  проход возвращает просроченные приглашения в общий пул; «Позвать друга» —
  открытая ссылка, её забирает первый открывший, запись резервируется на срок
  приглашения; дружеская дуэль вне зачёта (не идёт в пул, таблицу и рейтинг);
  раздел «Тренировка» (боты на уровнях, отработка ошибок); экран «Мои партии»;
  нижняя навигация из четырёх разделов; таблица результатов соло по `solo_score`;
  дневной банк наборов вопросов. Last Stand реализован отдельно
  ([COLLISION_MODE](docs/COLLISION_MODE.md)).
- **Размеры наборов покатегорийные:** география 20 вопросов и 12 наборов в банке
  дня; «Другие флаги» и «Языки» по 18 и 6 наборов. У флагов 44 сущности, у языков
  37, по одному шаблону вопроса; в географии 197 стран на семь шаблонов.
- **«Исторические флаги» переименованы в «Другие флаги»**, id `history` сохранён
  (входит в `question_set_id`).
- **Круг соло-забега считает сервер** (`d0a84ad`). Вопрос уходит клиенту через
  `toPublicQuestion` без ответа и пояснения; ответ и дистанция удара идут
  отдельными запросами, круги пишутся в `solo_run_rounds` по мере игры, повтор
  круга не засчитывается дважды. Поэтому закрытая вкладка больше не теряет забег:
  он продолжается с теми же кругами, отдельная офлайн-очередь соло не нужна.
  Клиент вопросы больше не генерирует: `sampleData` удалён, таблицы стран ушли
  из бандла (−56 КБ), тест падает, если данные ответов вернутся.
- **Отработка ошибок переехала на сервер** (`d9c00c0`, миграция 0011
  `player_mistakes`). `/api/training/check` раньше возвращал правильный ответ для
  любого id, а id лежали в payload живого забега. Теперь обе training-ветки
  отдают только вопросы, в которых игрок ошибался, и отвечают одинаковым 404 на
  всё остальное; вопрос из активного забега закрыт, пока игрок на него не ответил.
  Побочно: журнал вёл только режим гонки, так что у игравших соло тренировка была
  пустой.
- **Чит через reduced motion закрыт** (`6a060a1`). Клиент ставил маркер ровно на
  цель и не запускал движение, то есть при включённой настройке доступности
  каждый удар давал 25 из 25 и 100% достигались за четыре круга. Положение
  маркера теперь выводится из времени и скорости, это закреплено тестом.
  **Результаты, записанные до `6a060a1`, недостоверны.**
- **Категория по умолчанию — «Общие знания»** (`general`, DEC-07, 2026-10-12).
  Главная ведёт прямо в неё; география, «Другие флаги» и «Языки» выбираются
  кнопкой «Другие категории» на экране готовности забега. **Известная цена этого
  места:** забег к тому моменту уже создан, а подбор считает сыгранным любой
  набор со строкой в `match_runs`, доигран он или брошен, поэтому смена
  категории расходует набор дня. Вход с главной владелец убрал 2026-10-12.
  Набор дня — 20 вопросов:
  14 записей из пакета `content/` (657 записей, 16 тем) и 6 вопросов
  генераторов (3 география, 2 флаги, 1 языки); 4 пакетных подаются открытым
  вводом. Банк дня — 12 наборов, 168 записей из 657 за сутки без повторов.
  Собирает `generalSet.ts`, восстанавливает по id `questionResolve.ts`.
  **Весь пакет одобрен владельцем разом, без построчной вычитки**
  ([CONTENT_REVIEW](docs/CONTENT_REVIEW.md)).
- **Матч — это пара (DEC-09, 2026-10-13).** Запись достаётся первому, кто её
  нашёл, и больше никому: захват атомарным условным `UPDATE` (в D1 нет
  `SKIP LOCKED`). Держится по молчанию: три минуты без круга — запись уходит
  обратно в подбор, а пара рвётся (`pace_released`, миграция 0015). Завершённый
  матч запись не отпускает. Открытая ссылка другу живёт сутки, реванш — семь
  дней: ссылка держит запись вне подбора, реванш не держит ничего.
  Забег с `opponent_run_id` в пул не возвращается. Владелец записи видит, кто её
  сыграл (`played_by` в «Моих партиях»). Миграция 0014 добавляет
  `claimed_by`/`claimed_at`.
- **Реванш зовёт игрок** (R17, 2026-10-13). Приглашение создаёт нажатие того,
  кто обошёл запись (`POST /api/solo-runs/:id/rematch`), и только оно; кнопка
  живёт в «Моих партиях» у его забега. Известие об исходе стало просто
  известием: ни строки приглашения, ни кнопки, ни обещания реванша в тексте.
  Раньше строку создавало уведомление, и у владельца записи это выглядело как
  вызов, которого никто не посылал.
- **У таблицы дня появился экран** (R18, 2026-10-13): вход — ссылка «Таблица
  дня» на главной карточке (нижняя панель не менялась), внутри категории, топ-50
  по кругам и своё место над списком с подсказкой «до N-го места — M кругов».

  потому что занижен. **Сутки игры сдвинуты** с полуночи UTC на
  `DAY_BOUNDARY_OFFSET_MINUTES` (+5 часов = полночь в Алматы): по этой границе
  считаются и набор дня, и окно таблицы. Граница одна для всех. Следствие: id
  набора «сегодня» один раз сменится при переходе.

  присылает только момент удара (`activeElapsedMs`), а расстояние до цели и tier
  выводит общая `scoreHammerTap`: цель и скорость детерминированы по id вопроса
  и стадии, поэтому сервер считает ровно то, что игрок видел. Прежний payload с
  готовым `skillDistance` отклоняется 400; раньше одно число `0` давало 25 очков

## Главные пробелы

1. **Лимит 15 секунд на вопрос сервером не применяется, и нынешним протоколом
   применить нельзя:** набор уходит клиенту целиком, поэтому вопрос можно
   прочитать заранее и ответить когда удобно — любой дедлайн обходится выбором
   момента «начала». Для лимита набор нужно отдавать по одному вопросу, а это
   решение с ценой: предзагрузка картинок и возобновление забега после закрытой
   вкладки держатся на том, что набор уже у клиента. Решать владельцу.
   Сделано, что можно без смены протокола (R20): сервер мерит своё окно ответа
   (`answer_window_ms`) и отклоняет заявленное время больше окна. Оценка удара
   закрыта раньше (R16), утечка ответов (A06) — удалением гонки.
2. `setPar` считает пар по средней награде **21,47 очка** за верный ответ — это
   замер молотка до R5d, когда идеальных ударов было 60%. После сужения зон их
   около 21%, то есть реально выходит 16,8–18,9 очка, пар занижен на 12–22% и
   «1.0 = как эталон» больше не правда. Внутри одного набора порядок в таблице
   это не портит: пар у всех один. Константу намеренно не меняли: нового замера
   нет. Проверить, когда наберутся круги: `npm run calibrate:pricing` — он сам
   скажет, хватает ли данных (на 2026-10-13 не хватает: 31 круг, ударов с
   записанным моментом ноль).
3. Содержание пакета общих знаний не вычитано: 271 авторская запись имеет только
   подсказку, где проверять, а не источник. Ошибку найдёт игрок.
4. `setPar` оценивает вопрос по формату (выбор/ввод, текст/картинка), поэтому
   трудность конкретной записи в цену не входит. Посчитанный пар наборов почти
   совпадает: 8 у общих знаний, 8 у географии, 9 у флагов, 8 у языков — то есть
   разрыв между категориями мал, а грубость сидит внутри категории.
5. Проверить игру на настоящем телефоне. Визуал владелец утвердил как MVP
   2026-10-13: арт-направление больше не открытый вопрос.

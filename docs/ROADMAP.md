## R3 · Подтверждение и повторная отправка результата

Основание: A03. Модель: 5.6-Sol, medium. Зависимость: стабильный контракт R1/R2.

- **R3a: серверная часть выполнена вместе с R1b.** Completion проверяет результат
  conditional UPDATE и возвращает сохранённую запись при проигранной гонке.
  Повтор и два конкурентных payload проверены route-тестами. Очередь на клиенте
  этим не заменена; R3b/R3c остаются.
- **R3b:** небольшая durable-очередь отправки, видимый статус pending/saved/error,
  повтор transient-ошибок с ограниченным backoff и ручной retry. Не повторять
  безусловно 4xx; обработать expiry identity. ACK удаляет запись из очереди.
- **R3c:** reconcile серверного результата, dedup локальной статистики по matchId.
  Не смешивать несохранённую локальную практику с подтверждённым онлайн-матчем.
- Файлы: API complete, web `api.ts`, `useGameState.ts`, `localStats.ts`,
  `ResultScreen.tsx`; отдельный модуль очереди при необходимости.
- Готово: обрыв после сохранения на сервере, timeout, reload, повторный запрос
  и два параллельных completion не теряют и не удваивают результат.
- Восстановление незаконченного матча — отдельная следующая задача, не скрытое
  расширение очереди завершённых результатов.

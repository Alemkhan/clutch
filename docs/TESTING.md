# Тестирование Clutch

Автоматические проверки, ручной прогон в браузере и Telegram, туннель, частые проблемы.
Установка, переменные Worker и миграции — в [README](../README.md); деплой — в
[RELEASE](RELEASE.md). Команды выполняются из корня репозитория (PowerShell).

Локальный тест — не production: Vite на `5173`, Worker на `8787`, локальная D1, HTTPS-туннель
до Vite (Vite проксирует `/api`, поэтому для Telegram нужен один публичный URL).

## 1. Автоматические проверки

Перед ручным тестом и перед каждым checkpoint:

```powershell
npm test                          # vitest: shared, API-route-тесты на SQLite, web
npm run build                     # typecheck всех workspaces + production-сборка web
npm run test:smoke:local          # настоящий Wrangler + чистая D1
npm run test:preflight:production # fixture production-проверки (включает полный build)
```

- `node:sqlite` в route-тестах печатает предупреждение «experimental» — это ожидаемо.
- Целевой прогон: `npx vitest run <путь>`; проверка пака вопросов: `npm run content:check`.
- **Smoke** ([scripts/smoke-local.mjs](../scripts/smoke-local.mjs)): временные config и
  persist-каталог вне репозитория, миграции только `--local`, настоящий `wrangler dev`,
  затем по HTTP — `401` без авторизации, две guest-сессии, бот для A, завершение A, точная
  запись A для B, идемпотентный повтор; Worker и temp удаляются. Не читает `.dev.vars`,
  не использует Cloudflare-аккаунт. Он не эмулирует браузер и не доказывает
  offline/retry — это unit/route-уровень и ручной прогон ниже.
- **Preflight fixture** использует зарезервированный `.invalid` URL и фиктивные ID, строит
  production-config в temp и проверяет exact API URL в бандле. Это не проверка реальных
  production-ресурсов.
- CI (`.github/workflows/ci.yml`) выполняет `npm ci`, `npm test`, smoke и preflight fixture.
  Удалённый запуск на GitHub не подтверждён: локальный зелёный прогон его не заменяет.
- Для чтения локальной D1: `npm run reports -- --question gp: --limit 5` (репорты вопросов;
  также `--player`, `--kind`, `--mode`), `npm run activity` (`--days N`), `npm run player --
  guest:xxxx`.

## 2. Ручной прогон в браузере

Откройте `http://127.0.0.1:5173` (вне Telegram приложение работает как browser guest).
Health: `…:5173/api/health`, readiness D1: `…:5173/api/ready` (503 при `200` на health —
не применены миграции). Таблицу дня проверяйте через ссылку на главной:
`/api/solo-leaderboard` требует Authorization.

Минимальный сценарий:

1. Главная открывается без вечного loading.
2. «Играть» сразу начинает забег в «Общих знаниях» (экрана выбора нет); другая категория —
   «Другие категории» на экране «Забег готов». Набор дня к этому моменту уже выдан.
3. Запись соперника видна в HUD, но не завершает забег за игрока.
4. «Начать» открывает вопрос; на вопросе с картинкой варианты недоступны до загрузки media.
5. Разбор явно показывает правильный ответ; у неверного MC видны выбранный и правильный
   варианты; неверный ответ не даёт мини-игру.
6. Верный ответ открывает молоток; после ударов зоны сужаются и смещаются; в HUD виден
   прирост «+N».
7. Забег заканчивается на 100%, на потолке кругов или в конце набора. Круги сохраняются сразу;
   итог показывает подтверждённое сервером. Тренировка помечена как незачётная. Исход
   рейтингового забега на итоге **не** показывается — он в «Моих партиях».
8. Перезагрузка посреди забега продолжает тот же серверный забег.
9. «На глазок» (если в локальной D1 есть вопрос на сегодня): ввод, шаг подтверждения,
   вскрытие, повтор ответа не принимается.

### Mobile viewport (DevTools)

Минимум `360 × 640` и `390 × 844`. Дополнительно: длинный вопрос и варианты; open-answer с
экранной клавиатурой; поворот экрана; zoom 200%; `prefers-reduced-motion: reduce`; фон и
возврат; медленная сеть и ошибка загрузки картинки. Таймер не стартует до первой успешной
загрузки обязательного media и не замораживается скрытием вкладки.

### Плохая сеть

В DevTools → Network: во время вопроса включите `Offline` и ответьте — должен появиться
повтор запроса, а после `Online` ровно один круг записывается без дубля. Двойной тап по
«Начать» не создаёт два забега; Back во время загрузки подбора отменяет запрос, поздний ответ
игру не открывает; тренировка всегда помечена как незачётная.

## 3. Два игрока (настоящий соперник)

Нужны две **разные identity**: Telegram на телефоне и Desktop под одним аккаунтом — один
игрок. Вместо второго аккаунта можно открыть отдельную guest-сессию (InPrivate/Incognito) —
это проверяет подбор, но не заменяет проверку двух реальных `initData`.

1. Игрок A проходит забег до 100% в категории; в пустом пуле A видит соперником `Бот`.
2. Игрок B открывает ту же категорию в те же игровые сутки: должен увидеть `Запись игрока`
   с именем A. Запись достаётся одному: третий игрок её уже не получит (пара, DEC-09).
3. После финиша B в «Моих партиях» у A появляется исход и имя сыгравшего; у обладателя записи
   доступна кнопка реванша; Telegram-владельцу записи приходит известие.
4. Если замолчать на 3 минуты, запись вернётся в подбор, а экран скажет, что соперник отпущен.

Забег, не дошедший до 100%, ждущей записью не становится — тогда `Бот` для B правилен.

## 4. Telegram локально

Нужен публичный HTTPS URL; для ежедневной проверки проще стандартный Telegram и туннель.
Справки: [Telegram Mini Apps](https://core.telegram.org/bots/webapps),
[ngrok](https://ngrok.com/use-cases/share-localhost).

1. **Бот:** в `@BotFather` — `/newbot` (или существующий тестовый); токен положить в
   `apps/api/.dev.vars` (см. README). Токен должен принадлежать боту, через которого
   открывается Mini App, иначе проверка `initData` даст `401`. После правки `.dev.vars`
   полностью перезапустите `npm run dev`. В dev клиент всегда обращается к локальному
   Worker через Vite `/api` proxy: оставшийся в `apps/web/.env` production `VITE_API_URL`
   больше не уводит туннель на production API с токеном другого бота.
2. **Туннель** (второй терминал, `npm run dev` работает):
   - **Cloudflare Tunnel** — бесплатно, без заглушки; рекомендуется:
     `cloudflared tunnel --url http://localhost:5173`.
   - **ngrok** — `ngrok config add-authtoken …`, затем `npm run tunnel`. На бесплатном
     аккаунте ngrok отдаёт заглушку «ngrok-skip-browser-warning», а внутри Telegram пройти её
     нельзя: заголовки можно задать запросам клиента (в dev он их шлёт — `TUNNEL_HEADERS` в
     `apps/web/src/platform/api.ts`), но первую загрузку страницы делает сам WebView. Нужен
     платный план или Cloudflare Tunnel. На компьютере заглушку можно пройти кнопкой «Visit Site».
   - Адрес вставляйте без `:5173`. Бесплатные адреса меняются при каждом запуске.
   - Vite принимает `*.ngrok-free.app`, `*.ngrok-free.dev`, `*.ngrok.app`, `*.ngrok.io` и
     `*.trycloudflare.com`; свой домен — `$env:CLUTCH_DEV_ALLOWED_HOSTS = "my.example.com"`
     (через запятую). Чужой Host даёт «Blocked request. This host is not allowed» и по
     виду похож на поломку туннеля.
3. **Привязка:** `@BotFather` → `/setmenubutton` (текст «Играть», полный HTTPS URL) либо
   `/mybots` → бот → Bot Settings → Menu Button; для `Launch app` — Main Mini App. Прямая
   ссылка: `https://t.me/BOT_USERNAME?startapp`. После смены адреса туннеля обновите URL.
4. **Проверка:** личный чат с ботом → «Играть» → старт без `401`, на профиле имя
   Telegram-пользователя, забег доходит до итога.

Внутри Telegram отдельно проверьте: системную кнопку Back на каждом экране; safe areas;
клавиатуру на open-answer; сворачивание и возврат; звук и silent mode; шаринг результата
(`shareURL` закрывает Mini App — на телефоне не проверялось); «На глазок» и его шаринг;
панель «Сообщить о проблеме» поверх клавиатуры; доставку Telegram-сообщений (результат
записи, реванш, «выбили из десятки») и кнопки в них; реванш и «Позвать друга» по настоящим
ссылкам; Android и iOS; 60/120 Hz.

Для ежедневных сообщений включите «Ежедневные задания» в профиле Telegram. В production
cron начинает рассылку после 17:00 по Алматы; кнопки должны открыть непосредственно
«На глазок» и «Вики-путь», а «Отключить ежедневные сообщения» — выключить только эту
настройку. Повторный cron в те же сутки не должен присылать второе сообщение.

## 5. Просмотр локальной D1

```powershell
npm exec --workspace @clutch/api -- wrangler d1 execute clutch-db --local --command "SELECT id, player_id, category, rules_version, status, progress, reached_target, solo_score, solo_outcome, opponent_run_id, claimed_by, created_at FROM match_runs ORDER BY created_at DESC LIMIT 20;"
```

Смотрите: `status = completed` и `reached_target = 1` у записи, пригодной для пула;
`opponent_run_id` у забега против сохранённого игрока; разных `player_id` у двух аккаунтов;
круги — в `solo_run_rounds`. Очистить локальные забеги: `DELETE FROM match_runs;` через ту же
команду (`--local` обязателен; это необратимо только для локальной базы). Если схема
пересоздавалась, удалите локальное состояние D1 в `apps/api/.wrangler/state/` и примените
миграции заново.

## 6. Частые проблемы

- **`npm run dev` не запускается:** Node `v22.17.0` (`.nvmrc`), `npm ci`, свободные порты:
  `Get-NetTCPConnection -LocalPort 5173,8787 -ErrorAction SilentlyContinue` — остановите
  конкретный PID, не все процессы Node.
- **`no such table: match_runs`:** не применены локальные миграции (команда в README); потом
  перезапустите Worker.
- **В браузере работает, в Telegram `401`:** токен в `.dev.vars` чужого бота; Worker не
  перезапущен; открыто не через кнопку Mini App; устарел `initData` (закройте Mini App
  полностью); сильно неверное системное время. Не «чините» передачей `playerId` с клиента.
- **Telegram показывает старую версию или URL:** закройте WebView, проверьте текущий адрес
  туннеля, обновите URL в BotFather, убедитесь, что `npm run dev` жив.
- **Туннель отвечает 502:** Vite на `5173` не запущен; сначала откройте
  `http://127.0.0.1:5173`, затем перезапустите туннель.
- **Игрок B снова получил бота:** A не дошёл до 100% (`reached_target`); разные категории
  или игровые сутки; запись уже занята третьим; A и B — одна identity; база очищена или
  Worker использует другое persist-состояние.

## 7. Что этот тест не доказывает

- Production Cloudflare Worker, Pages, D1, секреты и remote-миграции; GitHub Actions до
  первого удалённого запуска.
- Поведение Telegram Android/iOS на устройствах, которые не проверялись вручную.
- Честность публичного рейтинга: время ответа заявляет клиент, подобранный момент удара не
  исключён ([AUDIT](AUDIT.md) A06).
- Редакторскую корректность контента (пакет «Общих знаний» одобрен без построчной вычитки;
  «Другие флаги»/«Языки» без источников) — [CONTENT_REVIEW](CONTENT_REVIEW.md).
- Новую палитру, лицензии всех ассетов, поведение на живых игроках.

Deploy и remote-миграции — не без отдельной команды владельца и плана отката из RELEASE.

## 8. Короткий ежедневный сценарий

```powershell
npm ci                                                                                    # один раз
npm exec --workspace @clutch/api -- wrangler d1 migrations apply clutch-db --local        # при новых миграциях
npm test; npm run test:smoke:local                                                        # перед ручным тестом
npm run dev                                                                               # терминал 1
cloudflared tunnel --url http://localhost:5173                                            # терминал 2, для Telegram
```

Затем: браузерный smoke → Telegram через menu button → два игрока (разд. 3) → mobile /
клавиатура / background / offline.

# Аудит текущего состояния

Дата исходного аудита: 2026-09-27. Текущий checkpoint: `3015241` с R7c. Метод: чтение web/API/shared, конфигурации,
миграции, тестов и предыдущего контекста; запуск существующих проверок.
Статусы A01/A02/A03/A04/A05/A07/A09/A10/A11 дополнены результатами R1–R7c и R5c на 2026-10-02.
Проблемы ниже выведены из кода, если отдельно не указано иное. Это не результат
пентеста, полной проверки контента или прогона на физических устройствах.

## Что уже работает как основа

Есть полный игровой цикл, общий HUD, три категории, shared-scoring, локальный
режим, async API и таблица D1. Не нужна смена стека или переписывание с нуля.
Главные недостающие части — согласованность правил, надёжность сетевого цикла
и качественная мобильная сцена мини-игры.

## A01 · Владение матчем закрыто в R2a; это не полный античит

R2a убрал `playerId`/initData из тела start. [Identity](../apps/api/src/auth/identity.ts)
проверяет `Authorization: tma` либо подписанный browser guest token; complete
сверяет `match_runs.player_id` до возврата уже завершённого результата. Чужой и
отсутствующий matchId неразличимы по ответу 404. Guest renewal сохраняет subject.

Это закрывает подмену Telegram id и запись чужого матча, но не доказывает
честность ответов/skillDistance и не создаёт полноценный аккаунт. Guest token
в localStorage остаётся bearer-секретом. R2b теперь ограничивает JSON start и
complete, поля/число раундов и guest/start/complete/leaderboard через нативный
Cloudflare Rate Limiting binding (30/60 секунд, отдельные ключи). Его счётчики
локальны для Cloudflare location, это не глобальная квота и не античит.
Production secret/deploy в аудите не проверялись.

## A02 · Согласованность завершения закрыта в R1

Исходно API принимал произвольный префикс вопросов, а раннее поражение попадало
в пул как неполный ghost. Теперь [API](../apps/api/src/index.ts) проверяет
terminal state через shared, сохраняет `ghost_eligible` вместе с результатом,
фильтрует совместимость версии/config и использует снимок соперника. Миграция
0002 не объявляет legacy-записи совместимыми задним числом.

Проверено 17 route/SQLite-тестами и основным сценарием в настоящем локальном
Wrangler/D1. [Клиент](../apps/web/src/lib/useGameState.ts) теперь использует
shared-переходы; [адаптер](../apps/web/src/lib/clientMatchRules.ts) проверяет
conditions/онлайн-транскрипт и отдельно нормализует fallback/challenge.
Защита владельца добавлена позже в R2a; достоверность scoring не решена.

## A03 · Закрыто R3 · Completion имеет durable ACK/retry-контур

[completionQueue](../apps/web/src/lib/completionQueue.ts) сохраняет canonical
payload и opponent progress в versioned localStorage без auth token. Bootstrap и
событие online запускают single-flight flush; transient network/408/425/429/5xx
имеют до четырёх попыток, terminal 4xx не повторяются. Retry-After учитывается,
исчерпанный transient-цикл можно запустить вручную. Очередь не вытесняет старый
несохранённый результат при лимите 20, а показывает ошибку нового enqueue.

В R1b [UPDATE](../apps/api/src/index.ts) проверяет число изменённых строк и при
проигранной гонке возвращает сохранённый результат. Последовательный повтор и
конкурентные разные payload покрыты route-тестами. Клиент удаляет запись только
после валидного ACK того же matchId, сверяет server progress/correct/rounds и
записывает outcome один раз. Реальный offline/reload walkthrough ещё не выполнен;
восстановление незавершённого матча не входит в R3.

## A04 · Закрыто R4 · Честный matchmaking и безопасный replay

[Matchmaking](../apps/web/src/components/Matchmaking.tsx) теперь разделяет
loading/ready/error и не показывает sample-имя до валидного ответа. Источники
player, bot, local и challenge имеют отдельные видимые подписи на lobby и итоге.
401/403 объясняются как проблема сессии/доступа; временная ошибка предлагает
retry либо явную локальную практику без сохранения.

[Координатор](../apps/web/src/lib/matchmaking.ts) обеспечивает один запрос для
текущего выбора, AbortController и монотонный token против late response. Back
инвалидирует запрос. Online replay проходит через новый start, challenge/local
сохраняют режим; подготовленный матч запускается один раз отдельной кнопкой.

## A05 · P1 · Условия skill-попытки зависят от устройства

[R5a](ROADMAP.md#r5--справедливые-тайминги-и-зоны-попадания) исправил HammerGame:
маркер теперь triangle-wave от активного elapsed time, с cap 50 мс на frame,
паузой при hidden и центром при reduced motion. Зоны weak/good/great/perfect
берут границы из общего scoring-источника. Нужна ручная визуальная проверка в
Telegram на физическом телефоне.

[R5b](ROADMAP.md#r5--справедливые-тайминги-и-зоны-попадания) исправил вопрос:
[TimerBar](../apps/web/src/components/TimerBar.tsx) выводит остаток из абсолютного
deadline, а hidden-время продолжает истекать и немедленно синхронизируется на
visibility resume. `QuestionScreen` использует один one-shot gate: в/после
deadline побеждает timeout, повторные click/Enter и гонка с expiry игнорируются.
Внутренний таймер открытого ввода удалён, delayed callback очищается на unmount.
Чистая логика покрывает throttling, большой скачок времени, resume, точный
deadline и обе очередности answer/expiry. Ручная проверка этих сценариев в
Telegram на физическом телефоне не выполнялась.
[R5c](ROADMAP.md#r5--справедливые-тайминги-и-зоны-попадания) добавил pressure
без device-зависимой кривой: shared stage, детерминированный target из question id,
stage thresholds и normalized distance одинаковы для отрисовки, gameSession и API.
Stage не доверяется клиенту и выводится из последовательности предыдущих non-miss
результатов. Ручная визуальная проверка смещённых зон на маленьком экране и в
Telegram на физическом телефоне не выполнялась.
Переход после удара зависит от animation callback; при переработке анимации
нужно сохранить однократное завершение, включая reduced motion и размонтирование.

## A06 · P1 до casual-беты; блокер защищённого рейтинга · Клиенту доверяют scoring inputs

[API](../apps/api/src/index.ts) отдаёт правильные ответы и всю запись
соперника. `skillDistance` и `responseTimeMs` приходят с клиента; сервер
последовательно пересчитывает pressure stage и награду, но не доказывает
честность исходной distance и не применяет 15 с.
Контент также включён в клиентский shared-пакет.

Нужен явно выбранный уровень защиты (DEC-03), разделение публичного вопроса
и ответа, серверная проверка допустимых событий. Простое скрытие
`correctOptionId` не делает игру защищённой. До публичного запуска также нужны
граница доверия к gameplay-входам: R2b ограничил тело/строки/раунды и частоту,
но клиент всё ещё сообщает ответ, время и `skillDistance`. Это отдельная работа,
не повод строить live PvP.

## A07 · P1/P2 · Пул зацикливается; leaderboard агрегирует несвязанные результаты

[Подбор](../apps/api/src/index.ts) предпочитает свежие подходящие записи. Новые наборы
генерируются только при отсутствии подходящего ghost: цепочка игроков может
наследовать один и тот же набор, а повторным игрокам возвращаются знакомые матчи.
R1b добавил совместимость версий/config и пригодность записей. Балансировки
сложности, срока жизни и политики разнообразия по-прежнему нет.

[Leaderboard](../apps/api/src/index.ts) независимо берёт MAX(progress),
MAX(correct_count), MAX(completed_at): показатели одной строки могут принадлежать
разным матчам. Группировка по player_id + display_name разделяет одного игрока
после смены имени. Выбирать реальную лучшую запись; до рейтинга определить,
можно ли вообще сравнивать сырые проценты на разных наборах вопросов.

## A08 · P1 · Контент требует редакторской проверки, генератор — крайних тестов

Автоматический `status: approved` в [генераторе](../packages/shared/src/questionGenerator.ts)
не означает проверку человеком. Поля источников/проверки предусмотрены типами,
но не образуют редакторский процесс. Пример для проверки формулировки — запись
Шри-Ланки в [countries](../packages/shared/src/countries.ts#L133); фактологический
выбор столицы в этом аудите не исследовался.

В неподключённом [questionBank](../packages/shared/src/questionBank.ts) ответ
о первой женщине-премьере противоречит собственному примечанию: не публиковать
заготовки без проверки. Нужны источники, однозначные формулировки и варианты
допустимых ответов, а не правило «так обычно отвечают».

У `generateMatch` после исчерпания 100 попыток MC добор вызывает open-генератор.
Для history/languages список пуст: при недостатке уникальных выборок возможен
вызов undefined. Для geography возможно вернуть неполный набор после лимита.
Обычные 10 вопросов проходят текущие тесты; нужны детерминированные крайние случаи.

R8a зафиксирован в [редакторском gate](CONTENT_REVIEW.md). Активный каталог —
197 стран, 44 исторических флага и 37 языков; генераторы превращают их минимум
в 1 450 возможных random question id без построчных source/verified metadata.
Проверка официальных источников уже нашла две фактические ошибки: `gq` всё ещё
указывает Малабо после переноса столицы в Сьюдад-де-ла-Пас в январе 2026 года,
а `bo` указывает Ла-Пас вопреки статье 6 Конституции Боливии, где столицей
назван Сукре. `lk/za/sz/nr/id` требуют точной формулировки или актуализации;
`xk/ps/tw/il` — отдельной нейтральной политики. History/languages и показанный
на home draft challenge не готовы к публичному трафику. Код в R8a не менялся:
исправления и исключения должны идти отдельными проверяемыми задачами.

## A09 · P1 · Мобильная и визуальная готовность не подтверждены

R7a исправил готовность media в
[QuestionScreen](../apps/web/src/components/QuestionScreen.tsx): 15-секундный
deadline создаётся только после первого успешного `load`, а до него prompt и
ответы скрыты. Ошибка не запускает timeout и показывает retry с перемонтированием
изображения; повторный `load` не меняет deadline. Изображения грузятся eagerly,
а [CSS](../apps/web/src/index.css#L585) использует `contain`, поэтому содержимое
флага или контура не обрезается. Плохая сеть и retry на реальном телефоне не
проверялись.

R7b исправил язык и базовую семантику текущей игровой вертикали. В
[index.html](../apps/web/index.html) теперь `lang=ru`; viewport сохраняет
`viewport-fit=cover`, но больше не запрещает pinch zoom. Resolution поддерживает
Enter/Space, видимый focus и one-shot continue; Hammer после удара получает
disabled-состояние, а отдельный polite status сообщает результат без дублирования
видимого текста. Timer не является live-region, полосы HUD имеют progressbar-
значения, timeout и состояние сохранения используют alert/status по срочности.
Ключевая разметка проверена SSR-тестами. Screen reader, pinch zoom, фокус и
открытый ввод с экранной клавиатурой на физическом телефоне не проверялись.

R7c убрал неограниченное ожидание до первого render: единственный React root
сразу показывает доступный loading shell, cached init ожидается не более 2,5 с,
а timeout/rejection открывают App с неблокирующим честным статусом. Viewport
монтируется независимо в фоне: зависший запрос не блокирует App или BackButton,
а поздний успех подключает динамические CSS vars и expand без второго root.

Системный Back теперь имеет lifecycle-safe listener: он скрыт на home и во время
question/resolution/hammer, а безопасные экраны возвращают на home/categories с
отдельным правилом challenge matchmaking. Активный layout использует
`--tg-viewport-height` с `100dvh` fallback; open-answer фокусируется и повторно
прокручивается при resize visual viewport, с очисткой listener/animation frame.
Автотесты проверяют timeout/rejection/late completion, cached Promise, зависший
и синхронно падающий viewport, mapping и cleanup. Telegram Android/iOS, реальная клавиатура, safe
areas, длинные тексты, закрытие и возврат из фона на телефоне не проверялись.

Спрайты/анимация отклонены владельцем; это известное ограничение, а не
субъективный результат нового визуального теста. План — [ART_DIRECTION](ART_DIRECTION.md).

## A10 · P2 · Границы компонентов и статистики пока прототипные

`useGameState`, `App` и ResultScreen привязаны к hammer/«ударам». После R1c config
берётся из текущего матча/challenge, но одного универсального HUD всё ещё мало
для полностью сменных мини-игр. Нужен небольшой контракт при следующей сцене.

[ResultScreen](../apps/web/src/components/ResultScreen.tsx) больше не записывает
итог при mount. `localStats` учитывает только подтверждённые online ACK и хранит
ограниченный список matchId для dedup; legacy practice-статистика намеренно не
мигрирует. Полноценного серверного профиля и cross-device sync по-прежнему нет.
В index.css больше 2000 строк с исходными и V2-переопределениями; консолидировать
по компонентам после фиксации визуального baseline, не переписывать всё разом.

## A11 · P1 перед релизом · Не закончен контур проверки и эксплуатации

Нет tracked CI. В R1b добавлены route-тесты на реальной SQLite с обеими миграциями;
старт → complete → следующий игрок отдельно проверен на локальном Wrangler/D1.
Автоматического браузерного end-to-end и on-device QA пока нет.
Корневой `deploy:web` вызывает отсутствующий web script. Wrangler содержит
ENVIRONMENT=development, нет оформленного разделения dev/prod и release checklist.
Это наблюдения репозитория, а не доказательство отсутствия удалённого деплоя.

[Analytics](../apps/web/src/lib/analytics.ts) хранит события в памяти;
`flush` нигде не вызывается, приёмника нет, analytics matchId отдельный от API id.
Health не проверяет D1. Нужны диагностика сетевых ошибок, корреляция с matchId,
минимальные продуктовые события без raw initData/секретов и политика хранения.

У ассетов есть общие credits в README, но нет пофайлового provenance/license
manifest. Нынешние звуки — готовые эффекты из описанных там пакетов, не новая
генерация. Нужны mute, проверка воспроизведения на целевых телефонах и учёт
источников изображений/аудио; лицензии внешних ресурсов здесь не перепроверялись.

## Сетка v2 (общая для всех задач)

- Поля экрана — 20 px; между секциями — 24; внутри карточки — 20.
- Между элементами — 12 или 8; подпись → значение — 4.
- Главная кнопка — высота 56, радиус 16; вторичная — 48 или 44; карточка — радиус 20.
- Кегли: 32 / 24 / 18 / 16 / 14 / 12. Числа — `font-variant-numeric: tabular-nums`.
- Связанные строки (свой/правильный ответ, список партий, таблица) — одна
  карточка с разделителями, а не стопка отдельных карточек.

## Чего нельзя

- **Цифры на макетах выдуманы** (214 ответов, «3-й из 41», «точнее 80%», 7 кругов).
  В коде — только поля из данных; нет данных — блок не показывается.
- Не менять награды, зоны, скорость маркера, условия победы и порядок исхода.
- Не показывать исход матча на итоге забега: он по-прежнему живёт в «Моих партиях».
- Не трогать нижнюю панель, сцену и спрайты молотка, палитру (ждёт выбора v6).
- Не начинать общий рефакторинг стилей; одна подзадача — один PR-размер.

## Подзадачи

Брать по одной. «Решение владельца» — сначала спросить, потом делать.

### R26a · Сетка отступов — только CSS

Привести отступы, радиусы и высоты кнопок к сетке v2 на главной, «Партиях»,
таблице, профиле, тренировке, разборе и итоге. Цвета и шрифты не менять.
Готово, когда: на 360 и 390 px отступы совпадают с макетами; `cssDuplicates`-тест
и `npm test` зелёные; длинные тексты не обрезаются.

### R26b · «← Назад» на корневых вкладках

На вкладках нижней панели («Партии», «Тренировка», «Профиль») убрать верхнюю
ссылку «← Назад»: это корневые разделы. На вложенных экранах (таблица, «На глазок»,
реванш) оставить. Системная кнопка Telegram не меняется.
Готово, когда: тесты `ScreenHeader`, `MyRuns`, `TrainingHub`, `Profile` обновлены.

### R26c · Разбор: одна кнопка внизу

`ResolutionScreen.tsx`: внизу всегда кнопка — «К мини-игре →» при верном ответе,
«Следующий вопрос →» при неверном; над ней строка «В этом раунде без мини-игры».
Тап по фону продолжает работать, кроме открытой панели репорта. «Сообщить о
проблеме» — текстовая ссылка. Свой и правильный ответ — две строки одной карточки,
свой зачёркнут. При таймауте подзаголовок «Время вышло» и без строки «Твой ответ».
Готово, когда: тесты разбора покрывают верно / неверно / таймаут / панель
репорта не продолжает разбор.

### R26d · Молоток: прирост виден в HUD

После удара: в HUD рядом с процентом чип «+N», в полосе прирост — отдельный
сегмент другого цвета; под подписью удара «До 100% — ещё N%». Над дорожкой —
подписи очков зон, центр — самый насыщенный цвет. Строка «Серия N · зоны стали
уже», если стадия давления выросла.
**Подписи зон и их ширины брать из shared-порогов** (те же, что считают scoring),
а не хардкодом из макета. Reduced motion: прирост появляется без анимации.
Готово, когда: тест проверяет, что подписи совпадают с наградами tier из shared,
а HUD показывает новый процент в момент результата удара.

### R26e · Итог забега: квитанция записи

`SoloResult.tsx`: под заголовком — строка «за N кругов · категория», три числа
(верных ответов, идеальных ударов, место в таблице дня), карточка «Твоя запись ·
ждёт соперника» с текстом про «Партии» и Telegram. Кнопки: «Сыграть ещё»
главная, «Позвать друга» и «Мои партии» — вторичные в одну строку.
**Данные:** верные и идеальные — из кругов забега; место — `you` из
`GET /api/solo-leaderboard` (только если дошёл до 100%, иначе блок скрыт).
Для «не дошёл» и тренировки — свои варианты без места и без карточки записи.
Готово, когда: тесты на дошёл / не дошёл / тренировка / дружеская дуэль;
состояния «Сохраняем…» и ошибка сохранения не сломаны.

### R26f · «Партии»: понятные исходы

Вызов: «Игрок X зовёт на реванш», строка «Обошёл тебя: N кругов против твоих M»,
кнопка «Принять реванш». История — одна карточка со строками: «N кругов против M»,
мета (категория · время · соперник), справа плашка исхода
(Победа / Поражение / Ничья / Ждём / Не дошёл).
**Данных сейчас не хватает** (проверено 2026-10-16): `MyRunSummary` несёт только
свои `roundsPlayed`, у соперника — имя; `MyRematchInvite` — только проценты обеих
сторон. Круги соперника в строке и в вызове — расширение ответа API, отдельный шаг
с тестом маршрута. Без него строка показывает свои круги, а вызов — как сейчас.

### R26g · Таблица дня: своё место с действием

Своё место — крупная цифра, строка «До N-го места — M кругов», кнопка «Сыграть ещё
набор» внутри карточки. Под заголовком «Обнулится через N ч · полночь по Алматы»
(считать от `DAY_BOUNDARY_OFFSET_MINUTES`). Список — одна карточка, своя строка
подсвечена. Внизу «При равных кругах выше тот, кто быстрее» — **пока это правда**;
после R25 текст меняется вместе с правилом.

### R26h · Главная и «На глазок» — частично требует решений

Можно сразу: «Новый набор через N ч» в шапке; карточка «На глазок» по сетке v2
с тёмной вторичной кнопкой; после ответа — строка «На глазок · ×1,0 · точнее N% ·
следующий через …» с кнопкой «Ответ дня» (поля уже есть в `TiebreakerAnsweredView`).
На главной после зачётного финиша — «Ты N-й сегодня. До N-1-го — M кругов» из
`solo-leaderboard`.

**Решение владельца, до этого не делать:**
- номер вопроса «№7» — в API его нет;
- «Ответили N» до ответа — сейчас `totalAnswers` отдаётся только ответившему;
  показывать его раньше значит менять контракт;
- короткая формулировка вопроса для карточки — нужно поле в контенте;
- «Поделиться результатом» в стиле Wordle — новая функция.

Вскрытие (`Reveal.dc.html`): промах крупно в начале, затем гистограмма с делениями
÷1000…×1000 и цветами «занизили/завысили», «Как прикинуть» свёрнут по умолчанию,
в конце «Следующий вопрос через …». Формулировку «Лучший ответ дня» вместо
«Ближе, чем 100%» согласовать с владельцем.

## Проверки для каждой подзадачи

Целевые тесты компонента, `npm test`, `npm run build`, `git diff --check`.
UI: 360 и 390 px, длинный текст, загрузка и ошибка, reduced motion, открытая
клавиатура там, где есть ввод. Браузерная эмуляция не заменяет проверку в Telegram
на телефоне — в отчёте писать, что проверено, а что нет.

# Отчёт #3 — живой тест основного solo-режима

Плейтест проведён вечером **2026-10-13**, разбор сделан 2026-10-14 по
локальной development D1, сообщениям игроков и актуальному коду. Это не
production-аналитика. Правила теста: `solo-to-100-v2`, общие знания — режим по
умолчанию; часть игроков также открывала geography/history и Last Stand.

Важная поправка к первому разбору: голосовые сообщения, помеченные как слова
Мираса, были расшифровкой сообщений Дамира (`Damir`, `Damirchik`, `damiraitu`).
Сам Мирас почти не давал отдельного фидбэка. Все жалобы Дамира ниже относятся к
основному solo-режиму: в `last_stand_runs` у него нет ни одной строки.

## Главный результат

Игрок может получить честный серверный вердикт и всё равно решить, что игра
сломалась. Экран разбора показывает только «Верно/Мимо» и пояснение, но не
показывает правильный ответ и не подсвечивает правильный вариант. При этом API
уже возвращает `correctOptionId` либо `correctAnswers` после ответа.

Это особенно заметно в двух случаях:

- вопрос «Кто написал картину „Олимпия“?»: Клод Моне и Эдуард Мане отличаются
  одной буквой, а после ошибки игрок не видит, какой вариант был правильным;
- вопрос «Назовите столицу страны с этим флагом»: пояснение начинается с
  названия страны («Это флаг Танзания»), которой среди вариантов-столиц не было,
  и только затем называет Додому.

У вопроса «Какая рыба самая большая в мире?» пояснение спорит с выбранным
«синим китом», но вообще не называет правильный ответ «китовая акула». В
замере вопрос дал 0 правильных из 5, четверо выбрали синего кита.

Вывод: явная строка `Правильный ответ: …` должна идти до пояснения для каждого
типа вопроса. Для multiple choice также нужны различимые выбранный и правильный
варианты.

## Открытый ввод: два разных дефекта

### 1. Fuzzy matcher принимает неправильные ответы

Действующая формула — `max(1, floor(длина / 5))` правок.

Следствия, воспроизведённые по коду и данным:

- вместо односимвольного `D`, `8` или `π` проходит любой другой символ;
- `1886`, `1996`, `1895` и `896` проходят вместо `1896`;
- длинный ответ длиной 31 символ получает до 6 правок.

В проверенной выборке было 13 коротких вопросов с таким классом ошибки. Это
ошибка правила проверки, а не контента.

### 2. Латиница поддерживается случайно

Матчер сравнивает ввод только с явным массивом допустимых ответов. В проверенной
выборке 30 из 79 открытых вопросов имели латинский вариант, 49 — нет. Шесть
игроков использовали латиницу там, где основной ответ записан кириллицей; пять
таких ответов не были приняты.

Примеры: `Fraddy` против «Фредди Меркьюри», `copper` против «медь», `Pi`
против «пи/π», `Word Wide` против `World Wide Web`.

Автоматическая транслитерация не решает весь класс: `copper` — перевод, а не
транслитерация. Нужны явные английские алиасы в данных и единая политика
сравнения для solo и training.

## Форматы, которые не прошли проверку

### Открытый контур страны

За две живые сессии: **1 правильный ответ из 37**. Без масштаба, соседей или
части материка похожими выглядят страны несопоставимого размера, например
Беларусь и Палау.

Решение для MVP: не выдавать `open_outline_country` в новых наборах. Resolver
старых question id сохранить для истории и отработки уже записанных ошибок.
Возврат формата возможен только после отдельного дизайна карты с контекстом.

### Формулировка столицы

«Напишите столицу: Белиз» дала 0 из 6; четверо ввели название страны. То же
наблюдалось с Эквадором и Гамбией. Формулировка должна явно просить город:
«Какая столица у страны Белиз? Напиши название города».

### Last Stand

| Причина выбывания | Забегов |
| --- | ---: |
| таймаут | 9 |
| закончились варианты | 2 |
| назван загаданный ответ | 1 |

Всего 13 запусков у четырёх игроков, средний результат — 1,8 круга из 12,
лучший — 4. В одном случае ответ клиента пришёл на 15 957 мс при лимите 15
секунд: игрок успел нажать, но круг уже был проигран, что воспринимается как
неверный verdict.

Загаданный ответ не изменил основной источник выбывания после DEC-08: им остался
таймер. Решение для текущего MVP — убрать вход Last Stand с главной, сохранив
код режима для будущего пересмотра. Выбор 3–10 соперников не решает проблему
таймера.

## Подтверждённые и неподтверждённые проблемы

Подтверждено:

- правильный ответ теряется клиентским состоянием до экрана разбора;
- fuzzy matcher ошибается на коротких и слишком щедр на длинных ответах;
- английские алиасы неполны;
- профиль использует локальную статистику старого режима, которую текущий solo
  flow не записывает;
- три приглашения на реванш остались с `notify_status = 'failed'`;
- метрика «круги» непонятна без объяснения «меньше — лучше»;
- вход Last Stand остаётся заметным на главной, хотя живой замер режим не прошёл.

Причина пока не подтверждена:

- почему Telegram не принял сообщения о реванше: текущий код не сохраняет HTTP
  status/описание ошибки;
- почему не слышно звук на конкретном телефоне: в проекте только `.ogg`, а
  ошибки `play()` подавляются;
- является ли крупное поле открытого ввода проблемой размера, клавиатуры или
  отсутствия промежуточной обратной связи — нужен walkthrough на устройстве.

## Принятый beta-cut R22

1. Показывать явный правильный ответ на разборе.
2. Ввести точное сравнение коротких/числовых ответов и ограниченный fuzzy для
   длинных; использовать одно правило в solo и training.
3. Не выдавать open-outline в новых наборах и уточнить формулировки столиц.
4. Скрыть Last Stand с главной без удаления реализации.
5. Следом: исправить смысл профиля, добавить диагностику звука/уведомлений,
   кнопку сообщения о проблеме и минимальную серверную аналитику.

Запросы про казахский язык, платные подсказки, free spins и интеграции с
образовательными центрами записаны как продуктовые идеи, но не входят в этот
стабилизационный этап.

Следующий живой замер имеет смысл только после R22. Нужно отдельно считать:
долю ошибок после показа правильного ответа, использование латиницы, результат
open-answer по длине, долю доставленных реваншей, устройство/платформу проблем
со звуком и причины выхода из solo-забега.

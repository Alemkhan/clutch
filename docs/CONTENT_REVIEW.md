# Редакторский gate контента

Сверено 2026-10-16. Документ не утверждает вопросы за владельца и не делает текущий
`status: approved` доказательством проверки. Цель — определить, что именно можно выпустить,
какие записи заблокированы и какие данные должен оставить редактор. Исходный аудит R8a
сделан 2026-10-02; модуль видео-челленджа удалён, категория «Исторические флаги»
переименована в «Другие флаги» (id `history`), `gq` и `bo` исправлены в данных.
Таблицы ниже, кроме отмеченных, не пересматривались.

## Пакет общих знаний

Контент живёт в `content/questions/<тема>.json` и `content/sets/<тема>.json`
(см. [content/README.md](../content/README.md)); код читает эти файлы через
`packages/shared/src/generalPack/`. Там **657 записей: 605 вопросов
с одним ответом и 52 закрытые категории** («назови планету земной группы»)
по 16 темам.

По происхождению:

| Источник | Вопросов | Наборов | Чем подтверждён |
| --- | ---: | ---: | --- |
| Wikidata (CC0) | 229 | 1 | `sourceUrl` на конкретную сущность |
| Написано для Clutch | 271 | 36 | только `sourceHint` — подсказка, где проверять |
| NotebookLM | 105 | 15 | вывод языковой модели |

**Владелец одобрил весь пакет 2026-10-12, двумя решениями и оба раза разом, без
построчной вычитки.** Решение зафиксировано полем `editorialStatus: "approved"`
в каждой записи. Что это значит честно:

- Факты авторских записей никто не сверял с источником. Ошибка в них дойдёт
  до игрока, и обнаружит её игрок.
- Записи Wikidata настолько верны, насколько верна Wikidata на день выгрузки.
  Повторная выгрузка может молча изменить ответ.
- **Записи NotebookLM — самый рискованный слой.** Это вывод языковой модели:
  неверный факт в нём выглядит так же уверенно и правдоподобно, как верный,
  и источника за ним нет вообще. Если жалоба на вопрос придёт, начинать
  проверку стоит с них.
- `npm run content:check` доказывает только внутреннюю непротиворечивость:
  уникальные id, три различных неверных варианта, ни один неверный вариант не
  засчитывается при вводе, у каждого участника набора однозначное распознавание.
  Это проверка формы, а не истинности.

Обратная дорога открыта: `editorialStatus: "blocked"` убирает запись из игры, не
удаляя её. Разумный следующий шаг — вычитывать темами по мере жалоб, начиная
с NotebookLM и авторских `Hard`/`Expert`.

Рабочие команды: `npm run content:check` (проверка формы),
`npm run content:import -- файл.json` (добавить, по умолчанию `pending`),
`npm run content:wikidata` (дописать новое из Wikidata).

## Что реально попадает в игру

| Источник | Активность | Объём | Текущее состояние |
| --- | --- | ---: | --- |
| `content/questions/`, `content/sets/` | Да, основная категория `general` (и замороженный Last Stand) | 605 вопросов + 52 набора | Одобрено владельцем целиком, построчной вычитки не было |
| `countries.ts` | Да, random geography | 197 стран; 1 369 возможных random question id | Нет построчных источников и алиасов |
| `historicFlags.ts` | Да, random history (категория «Другие флаги») | 44 записи | Нет источников фактов и пофайлового provenance |
| `languages.ts` | Да, random languages | 37 записей | Нет источников фраз/фактов и языковой проверки |

География создаёт 591 MC-вопрос по флагу/столице, 192 MC-вопроса по
контуру, 394 open-answer по столице/флагу и 192 open-answer по контуру.
Это потенциальный каталог, а не 1 369 вручную проверенных формулировок.

Все генераторы сейчас автоматически возвращают `status: approved`, но не
заполняют `sourceUrl`, `sourceTitle` и `lastVerifiedAt`. Поэтому это технический
флаг старого прототипа, а не редакторский статус.

## Вердикт для traffic-ready MVP

- **География — условно пригодная база**, только после исключения известных
  ошибок/неоднозначностей и проверки оставшегося реестра стран, столиц, флагов,
  контуров и допустимых ответов.
- **«Другие флаги» (`history`) — заблокированы целиком** до построчной проверки.
  Категория смешивает государства, компании, армии, пиратский флаг и действующие
  городские флаги. Эпохи и эмоциональные `factRu` нельзя публиковать без источника.
- **Языки — заблокированы целиком** до проверки фразы носителем/авторитетным
  языковым источником и переписывания неподтверждённых `factRu`. Узнаваемый
  алфавит не доказывает точность перевода, регистра или объяснения.

Рекомендация аналитика для первого трафика: выпустить один проверенный набор
географии, а history/languages скрыть feature gate до отдельного
редакторского sign-off. Это предложение; решение владельца ещё не зафиксировано.

## Иерархия источников

Для каждого утверждения нужен источник, который действительно подтверждает
именно его, а не просто содержит похожее название.

1. Конституция, закон, официальный вестник, парламент или правительство страны.
2. Для кодов и нейтральных названий — [ISO 3166](https://www.iso.org/iso-3166-country-codes.html),
   [список членов ООН](https://www.un.org/about-us/member-states) и
   [UNTERM/редакторское руководство ООН](https://www.un.org/dgacm/en/content/editorial-manual/country-names).
3. Для русских отображаемых названий — CLDR как языковой справочник, но не как
   доказательство политического статуса или столицы.
4. Для языков — [ISO 639](https://committee.iso.org/iso-639-language-code) и
   CLDR для code/script; сама фраза проверяется носителем либо национальным
   языковым институтом. Популярный блог не утверждает перевод.
5. Для исторического флага — официальный архив/музей либо исследовательское
   издание; для файла отдельно фиксируются оригинальная страница и лицензия.
   Wikipedia может помочь найти источник, но не служит финальным источником.

Дата проверки обязательна. Столицы и государственные статусы проверяются перед
каждым публичным релизом; стабильные названия — минимум раз в год.

## Допустимые ответы

`correctAnswers: [nameRu, name]` недостаточно для русскоязычного open-answer.
Нужен явный список на уровне проверенной записи:

- канонический ответ, который показывается после вопроса;
- допустимые русские варианты: `ё/е`, дефис/пробел, короткое и полное название;
- английский вариант — только если редактор сознательно разрешил его;
- историческое/альтернативное имя — только если оно верно для формулировки;
- запрещённые близкие ответы, если fuzzy matching может спутать короткие названия.

Предлагаемая нормализация: Unicode NFKC, регистр, повторные пробелы, варианты
апострофа и дефиса, `ё → е`. Fuzzy matching не должен сам создавать новые
«правильные факты»: для ответов до четырёх символов безопаснее точный alias,
а порог для длинных ответов надо покрыть парами positive/negative. Это правило
ещё требует утверждения владельца и отдельной coding-задачи.

## Минимальная редакторская запись

Перед `approved` у элемента должны существовать:

```text
editorialStatus: pending | approved | blocked
canonicalAnswerRu
acceptedAnswersRu[]
sourceUrl[]
sourceTitle[]
sourceCheckedAt
reviewedBy
reviewNote
assetSourceUrl
assetLicense
```

`approved` наследуется вопросом из проверенной записи, а не проставляется каждым
генератором автоматически. При изменении ответа или источника старые match/ghost
нельзя молча смешивать с новым набором: требуется content version.

## Медиа и права

- README содержит общий credit для FlagCDN и mapsicon, но этого недостаточно
  для audit trail конкретного вопроса.
- Комментарий `CC0-friendly` у mapsicon неверен: репозиторий использует
  собственное условие «указать автора, не перепродавать». См.
  [оригинальный README](https://github.com/djaiss/mapsicon). До коммерческого
  трафика нужна явная проверка совместимости или другой источник контуров.
- 44 исторических изображения помечены лишь как скачанные с Wikimedia Commons.
  Commons предупреждает, что лицензия и атрибуция различаются по файлам;
  необходимо сохранить URL file page, автора, лицензию и дату загрузки для
  каждого файла: [правила повторного использования](https://commons.wikimedia.org/wiki/Commons%3AREUSE).

## Решения владельца перед публикацией

1. Первый MVP — только проверенная geography или сразу три категории?
   Рекомендация: geography-only.
2. Исключаем `xk/ps/tw/il` из первого пула или утверждаем нейтральные prompts?
   Рекомендация: исключить до отдельной политики.
3. Принимаем ли английские ответы в русской игре? Рекомендация: да, но только
   явными aliases, не автоматически для всех записей.

## Критерий завершения контентного gate

- Каждая активная запись либо `approved` с источником/датой/алиасами, либо не
  может быть выбрана генератором.
- Известные блокеры выше имеют регрессионные тесты.
- Генератор не создаёт `approved` из непроверенной строки.
- Для каждого локального изображения есть provenance/license manifest.
- В релизном checklist записаны content version и дата последней проверки.

До выполнения этих пунктов текущий банк подходит для прототипа, но не для
перегона публичного TikTok-трафика.
